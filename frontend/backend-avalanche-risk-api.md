# 雪崩风险与置信度瓦片接口提示

本文档供后端实现“积雪遥感”页面的两个新增图层使用。前端已按本文约定完成图层切换和联调，默认展示雪崩风险图层。

## 一、前端当前约定

前端已新增以下 XYZ 瓦片地址：

| 图层 | 瓦片地址 | 缩放范围 | 默认状态 |
|---|---|---|---|
| 雪崩风险 | `/api/tiles/avalanche-risk/{z}/{x}/{y}.png` | z6 ~ z14 | 默认图层 |
| 雪崩置信度 | `/api/tiles/avalanche-confidence/{z}/{x}/{y}.png` | z6 ~ z14 | 可切换 |
| MODIS 积雪 | `/api/tiles/modis-snow/{z}/{x}/{y}.png` | z6 ~ z11 | 现有图层 |

请求方式为 `GET`，认证规则请与现有 `/api/tiles/modis-snow/` 保持一致。

前端可能追加缓存版本参数，例如：

```text
/api/tiles/avalanche-risk/8/190/89.png?v=1762066800000
```

后端可以忽略 `v` 参数。

## 三、必须实现的接口

### 1. 雪崩风险瓦片

```http
GET /api/tiles/avalanche-risk/{z}/{x}/{y}.png
```

建议按以下规则渲染为 RGBA PNG：

| 原始值 | 含义 | 前端图例颜色 | Alpha |
|---:|---|---|---:|
| 0 | 无风险背景或无数据 | 不显示 | 0 |
| 1 | 0.55 ≤ score < 0.70 | `#fff7bc` | 255 |
| 2 | 0.70 ≤ score < 0.80 | `#fb6a4a` | 255 |
| 3 | score ≥ 0.80 | `#a50f15` | 255 |

### 2. 雪崩置信度瓦片

```http
GET /api/tiles/avalanche-confidence/{z}/{x}/{y}.png
```

建议按以下区间渲染为 RGBA PNG：

| 置信度区间 | 前端图例颜色 | Alpha |
|---|---|---:|
| value ≤ 0 或背景 | 不显示 | 0 |
| 0.70 ≤ value < 0.80 | `#dbe9f6` | 255 |
| 0.80 ≤ value < 0.90 | `#73b3d8` | 255 |
| 0.90 ≤ value < 0.95 | `#2389bd` | 255 |
| 0.95 ≤ value ≤ 1.00 | `#08306b` | 255 |

如后端选择连续色带渲染，请保持背景透明，并确保整体视觉顺序与前端图例一致。

## 四、空间与缩放要求

1. 原始数据已经是 `EPSG:4326`，无需重投影。
2. 瓦片坐标采用标准 Web Mercator XYZ 方案。
3. 建议预生成或缓存 z6～z14。
4. 地图最大缩放级别为 z14，不必生成更高层级。
5. 对数据范围之外的瓦片，建议返回透明 PNG；也可以返回 `204 No Content`。
6. 不建议对无数据瓦片返回 HTML 错误页，避免浏览器记录大量瓦片错误。

阿勒泰中心点示例：

```text
经度 88.3，纬度 47.1
z=8, x=190, y=89
```

可用于冒烟测试：

```bash
curl -i "http://<服务地址>/api/tiles/avalanche-risk/8/190/89.png"
curl -i "http://<服务地址>/api/tiles/avalanche-confidence/8/190/89.png"
```

预期：

- 已认证且瓦片存在：`200 OK`
- `Content-Type: image/png`
- 风险图主体区域返回非透明 RGBA PNG
- 背景或范围外区域透明

## 五、缓存建议

- 该数据是固定 2023 年成果数据，不需要每日追新。
- 建议预生成瓦片并在磁盘或对象存储中缓存。
- 支持 `ETag` 或长期 `Cache-Control`。
- 前端更新后可能追加 `?v=时间戳`，后端无需特殊处理。
- 如果重新生成瓦片，请保证最终 URL 不变，避免前端改动。

## 七、实现方式建议

可复用现有 MODIS 瓦片工作流，仅增加数据源适配和颜色映射：

1. 读取 GeoTIFF。
2. 将经纬度范围转换为当前 XYZ 瓦片对应的栅格窗口。
3. 重采样到 256 × 256。
4. 按上述分类或区间生成 RGBA 颜色。
5. 将背景值设为完全透明。
6. 输出 PNG 并缓存。

推荐处理要点：

- 风险分类图使用最邻近重采样，避免风险等级之间产生无意义过渡值。
- 置信度图可使用双线性重采样。
- 边界瓦片超出数据范围的部分必须保持透明。
- 对认证失败返回与现有接口一致的 401 响应。

## 八、需要数据提供方确认的问题

1. 风险分类值 `0` 是否同时表示“无风险”和“无数据”；如需区分，应提供独立掩膜或明确的 `NoData`。
2. 阈值边界建议采用左闭右开：
   - `1`: 0.55 ≤ score < 0.70
   - `2`: 0.70 ≤ score < 0.80
   - `3`: score ≥ 0.80
3. 置信度图的非正值是否都可以按背景透明处理。
4. 最终瓦片路由如果不用本文建议名称，需要同步更新前端配置。
